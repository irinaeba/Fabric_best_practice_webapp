Microsoft Fabric security

Choose the right Fabric access path

A practical guide for service principals that separates workspace and item access from OneLake roles, SQL grants, runtime networking, and endpoint authentication.

ABFS HTTPS 443 SQL TDS 1433 Auth Entra service principal Least privilege scoped data grants
Two permission planes: workspace roles and item permissions control which artifacts a principal can reach; OneLake roles or SQL permissions control which data it can read. Workspace roles cross both planes because they include default item and data permissions.
Critical: workspace roles can override granular access. Fabric effective permissions are additive. A broad workspace role carries default data permissions that a narrower item permission, OneLake role, or SQL GRANT cannot take away. Always check workspace membership first when a principal can see or read more than expected.

Viewer is not Read + ReadAll: Viewer receives Read + ReadData. This enables broad delegated SQL reads, but not direct ABFS access. Lakehouse SQL User identity mode evaluates OneLake security instead.
Least-privilege action: Admin, Member, and Contributor inherit SQL CONTROL and OneLake write access, so granular grants cannot narrow their access. Remove workspace-role membership first, then share only the required item through item-level permissions.

ReadData and ReadAll are independent: ReadData governs delegated SQL reads. ReadAll governs OneLake access through DefaultReader. Neither converts into the other, and both are broader than a schema/table-specific grant.

Least-privilege data grant after item Read

Lakehouse

Add a scoped OneLake security role for direct ABFS or SQL User identity mode. For SQL Delegated mode, add granular SQL permissions instead.

Warehouse

Add granular SQL permissions for restricted access. Do not grant ReadAll when SQL restrictions must remain authoritative.

Avoid broad ReadData or ReadAll when selected objects are sufficient. Validate each connection path independently after permission changes propagate.

External application scope: this section describes how applications outside Fabric, such as Palantir Foundry, custom services, ADLS Gen2-compatible clients, and SQL tools, authenticate and receive authorization to read Fabric data. Choose the Fabric item type first, then the connection method.
ABFS success does not prove SQL connectivity: ABFS and SQL can use the same service principal, but they are different client capabilities, token audiences, protocols, ports, endpoints, and authorization layers.

Use ABFS when

You need direct OneLake reads through an ADLS Gen2-compatible client. Least privilege must come from OneLake security roles where supported, or from broader OneLake item permissions such as ReadAll.

Use SQL when

You need Warehouse table access or SQL controls such as schema/table grants, row-level security, column permissions, views, procedures, or masking. Item Read enables connection; data still requires SQL authorization or inherited ReadData.

SQL endpoint path

Tokenhttps://database.windows.net/.default
›
DataMSSQL/TDS over TCP 1433

The SQL scope is an OAuth audience requested from Microsoft Entra; it is not a hostname to allowlist. Network traffic still goes to Entra over HTTPS/TCP 443 for the token and to the Fabric SQL endpoint over TCP 1433 for TDS.

Use a SQL Server JDBC/ODBC connector that explicitly supports Microsoft Entra service-principal authentication, encryption, the Fabric endpoint hostname, and the correct Warehouse or Lakehouse SQL database.

Warehouse over SQL endpoint

Least privilege permissions setup

  1. Do not assign a workspace role.
  2. Grant item-level Read on the Warehouse. This enables SQL connection only.
  3. Grant only the required SQL schema/table permissions.
GRANT SELECT ON SCHEMA::[required_schema]
TO [service-principal-name];

SQL permissions can provide object-, schema-, row-, and column-level controls within the TDS/SQL execution path.

External runtime network requirements — expand to view
  • Allow outbound MSSQL/TDS traffic to the Fabric SQL endpoint hostname on TCP port 1433.
  • Classify the traffic as Microsoft SQL Server MSSQL/TDS, not HTTPS.
  • If the firewall supports SQL-aware FQDN rules, an allow rule for the Fabric SQL endpoint on TCP 1433 can be sufficient.
  • If egress is controlled by Azure service tags or IP ranges instead, the documented PowerBI and Sql service tags are implementation options, not Fabric permissions.
  • Allow Microsoft Entra HTTPS endpoints required for service-principal token acquisition.
  • From the actual runtime, run Test-NetConnection <warehouse-endpoint> -Port 1433. A timeout indicates a network issue; a SQL/ODBC error means the TCP path is open.

Warehouse over OneLake / ABFS

Least privilege permissions setup

  1. Grant item Read for Warehouse discovery.
  2. Grant item ReadAll for direct access to all Warehouse files.
  3. For external clients, enable the tenant setting that permits external OneLake access.
  4. Use the ABFSS path from Spark or the OneLake DFS endpoint from an ADLS Gen2-compatible client.
abfss://<workspace>@onelake.dfs.fabric.microsoft.com/<warehouse>/...
The Microsoft Learn supported-item table does not currently list Fabric Warehouse for OneLake security roles (as of October 2026). There is no indication of a timeline for a future feature release as of now.
Security boundary: ReadAll exposes all files in the Warehouse. For access restricted to selected schemas, tables, rows, or columns, use the SQL endpoint with granular SQL security instead.
