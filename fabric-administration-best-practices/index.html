Microsoft Fabric
Best Practices Guide

A practical onboarding guide for Abu Dhabi government data teams setting up Microsoft Fabric with UAE data sovereignty, security, and operational best practices.

Who is this for?

This guide is designed for data teams in Abu Dhabi government entities who have provisioned a Microsoft Fabric capacity and need to:

  • Configure the Fabric tenant for UAE data sovereignty requirements
  • Set up workspaces, security, and access controls
  • Design a data architecture with proper naming conventions
  • Implement CI/CD and lifecycle management
  • Establish governance standards for artefact creation
⚠ UAE Data Sovereignty
Several Fabric features process data outside the UAE region and must be disabled for government workloads. See Section 2: Tenant Configuration for the full list.

Key Principles

ℹ Design Philosophy
  • UAE-first: All data processing stays within UAE. No exceptions for production workloads.
  • Least privilege: Grant minimum necessary permissions at every layer.
  • Modular workspaces: Separate by function to simplify CI/CD and security.
  • Consistent naming: Follow the DGE naming convention for all artefacts.
  • Automate delivery: Use Git + deployment pipelines for all promotions to production.
